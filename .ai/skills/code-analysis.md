# Skill: análisis de código

1. Ubicar el módulo con `context/Modulo-Map.md` y `chunks/module-index.md`.
2. Buscar por nombre de dominio (grep) antes de abrir archivos; abrir solo los relevantes.
3. Leer en este orden: tipos y esquemas (`packages/shared`) → servicio → controlador → pruebas.
4. Anotar: puntos de entrada, dependencias externas, transacciones y validaciones.
5. Si el hallazgo sirve para futuras sesiones, resumirlo en 1 a 3 líneas en `context/Modulo-Map.md`.
6. No proponer cambios hasta haber leído las pruebas existentes del módulo.
